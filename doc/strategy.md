## How a test case reports success or failure

A comparison, a return, and an assert are the ways the body records its own result.

- Happy Path can show all success modes at once
- Unhappy path needs individualised examples.
- When can a test fail
	- config
	- pre
	- setup
	- run
	- cleanup
	- post
- How are failures triggered
	- fail on assert
	- fail on bad return code
	- fail on bad runcode
- What changes the runcode
	- manual change
	- Check Functions
		- check
		- refuse

### Failures Cases
- We need a strategy to run the following matrix
	- phase{config, pre, setup, run, cleanup, post} * {assert, retcode} * runcode{manual, functions...}

Title and Description can be generated by the matrix

Such a thing should not explode the test_tree, instead the session should generate the cases when it is run.

An accompanying options resource can be used to configure the Strategy when say a matrix like the above needs to be trimmed during development.
